# 出题流程

主智能体负责完整题包，按需委派独立工作。新题依次执行下列阶段；指定旧题按第一节分支执行。技能只组织工作，不提供联网、下载、PDF、办公文档或浏览器工具，无法完成的环节须如实记录。

## 核心要求（探索前掌握）

- 国内真实项目或事项，成果服务于一个明确业务决定。可设计合理审查任务，不虚构真实委托、个人经历、付费或采用记录。
- 先核读原始证据并验证核心解答，再定稿。难点来自证据、参数和业务判断的依赖关系，不能用资料数量、长计算链、格式漏项或缺材料代替难度。
- 输入至少6份实际取得、可独立阅读且实质相关的公开材料，以多份内容充实的长篇原始材料为骨干。HTML最多1份，禁止网页转Word、PDF等绕过限制。完整计数及缺件处理见第三节。
- 每题嵌入服务于主决定、需要实际构造、计算和复核的小问题，见第四节。
- 被测模型只交一份Word（.docx），不要求表格或额外文件。出题者用十二字段Markdown表格保存题目，标答只用完整文字；逐考点全对得该项满分，否则该项0分，总分100；每题的考点字段必须明写评分规则。
- 难度门槛：指定SOTA模型得分≤50分，且执行步数≥50步或运行时间>40分钟。默认不调用外部被测模型，无对应版本真实测试记录即为“待实测”。出题耗时、子智能体复核、自评和旧答卷调权均不能替代实测。

## 一、初始化、查重与修订分流

以下初始化与查重用于新题；指定旧题直接执行本节修订分支。新题准备项目内的 `项目文档/已出题题单.md`、`笔记.md`、`题目收集/`，保留已有文件。随包基线分别位于 `references/已出题题单.md` 和 `references/笔记.md`。

先在本地比较项目记录与随包版本，不把两份全文都打印到上下文。相同只读一份；缺少项目记录时复制基线后读取；不同时完整读项目记录，再读取随包新增、缺失或冲突部分及理解它们所需的上下文：

- 题单按编号补入基线缺失条目，保留项目新增和已有修订。同编号冲突保留项目正文，本轮查重同时考虑两种描述。
- 笔记结合使用，保留来源和测试版本，不用基线覆盖新发现，不擅自判定旧结论失效。只有新测试证据才更新项目笔记，区分用户转述、已有评分、独立复评和事后回算。

查重只用精简题单，不扫描历史题包或重建索引。按真实对象和核心任务避重，改标题、日期、权重、地名或数字不算新方向；同一行业或共用法规不自动重复。相近候选直接换方向。题单无法读取时不能声称完成查重；现有题库缺少项目题单时，说明只覆盖随包历史。

指定旧题：读取该题及必要材料，判断修改影响到哪些事实、计算、评分和附件，仅重做受影响环节。沿用原目录及编号，完成后更新该行。若用户要求另存版本，使用新编号并注明源题。纯文字修改不重新探索候选、合并基线或重做全题验收，读取对应题单行以便同步，核对润色不改变实质条件。未复验部分保留既有状态，不能将润色完成表述为全题验收通过。

随包记录是打包时快照。出题只更新当前项目，团队共用最新项目记录；打包新版本时同步最新题单与笔记，不宣称自动同步其他电脑。

## 二、探索并确定方向

结合能力笔记通常比较2—3个具体候选；用户已指定对象或候选明确时不机械凑数。独立候选调查量较大时，可委派分别探索，由主智能体选定一个，不让各子智能体制作完整题包。

打开官方或原始发布页，核读关键内容并确认真实下载入口，不以搜索摘要、新闻转述或猜测URL当作已验证来源。候选应同时满足：

1. 明确谁使用成果、作什么决定、错误有何影响，任务来自真实工作流程且有实质专业价值，例如专业人工通常需16小时以上、周期性节省工作，或影响预算、成本、服务及合规；价值依据须可说明，不虚构工时或采用证据。
2. 已核实关键事实及足以判断可解性的计算，确认至少6份材料的来源、实质用途和可取得性，满足第三节长材料及格式要求；本地保存受限仅按待补规则处理。不依赖私有台账、未公开合同、私人账号或付费权限。
3. 多个判断服务于同一决定，版本、证据或统计范围的选择会改变参数、计算或处理意见。
4. 主要得分要求可得具体可核验结果，不能大部分只回答“待核实”；简单摘要、照表复算或套模板不能完成主要任务。
5. 结果能在单份Word中说明，并能设计第四节的小问题。

选定前检查最短解题路径：哪些原始明细必须重建，哪些证据判断会改变后续参数，哪些约束会改变方案。若只提取少数汇总值、套常规模型并写一般补证意见就能完成主要任务，不能因附件长或计算冠以“优化”就认定耗时充足。优先选择公开材料能支持、核对结果会传导到计算和采用意见的任务；不靠强制等待、工具次数或无意义重复拖长时间。

不满足时调整或换候选，沿用已核实的有效证据，避免选定后重新泛搜。依据笔记，在《出题记录.md》简记“具体材料条件→可能误判→后续结果影响”，不写入题干；能力反馈只代表既有测试，不假定模型必错或原件必有错误。

## 三、取得材料并建立证据记录

主智能体先确定真实对象、审查时点及材料版本。需要分工时按业务问题划分，例如资金依据、能力约束、审批适用，不机械按附件数量拆任务。主智能体检查跨材料关联、冲突及重复计入。

### 来源与核读

- 区分发布、成文、施行、修订和下载日期；历史任务不将后来材料当作当时已知事实。核对正式稿、征求意见稿、修改单、地方范围及条款效力。
- 优先官方或原始发布机构的PDF、Word、Excel原件。公开镜像或转载须注明实际发布者、承载平台并核验身份和版本。不得编造台账、合同、申请或数据文件作为输入。
- 下载后检查真实格式、完整性、可打开性和关键页可读性，排除错误页、验证码和空文件。中文命名并保留原件内容。目录中列有附件不代表原件已取得。
- 长材料先看目录和结构，再读相关章节、附表及适用条件，不能只做关键词命中摘录。关键表格、扫描件和提取异常回看原页，防止把OCR错误当成原件错误。尚未核读部分不能声称已核验。
- 证据记录包含文件名、完整来源URL、机构、日期版本、真实下载URL、取得和核读状态、页码/条款/表号、参数单位、期间分母及计量状态。区分PDF顺序页和正文页码。在《出题记录.md》集中记录以上信息，并记附件实际页数或内容规模、长材料骨干、跨附件关系及用途。题目附件字段列明所需文件及必要来源和取得状态。

提取全文和计算日志保存在题包之外的工作目录，避免反复输出到对话；向主线程回传必要结果和定位。主智能体回查决定解答的关键证据，不能只接收无法定位的摘要。最终答案必须自足，不依赖工作日志、历史对话或制作记录才能读懂。

### 附件计数与格式

每份计数材料须已保存、独立可读，并为同一决定提供必要事实、规则、参数或核对依据。多份长篇报告、规划及附表等应含有独立分析价值，证据分布于不同章节并共同影响判断。短通知只作必要补充，不用一份长报告加多份短通知凑数，也不靠重复内容、无关汇编、字号或分页制造篇幅。

同一材料的拆章、分页、截图、重复格式、镜像仅计1份；原报告附表另存不增加份数，发布机构单独发布且内容独立的附件可分别计数。链接、压缩包外壳、网页样式图片、来源清单、题目、答案及制作记录不计数。

HTML限额包括.htm、.html及等效网页文件。网页正文只能在此限额内按[HTML规范](项目文档/html风格.md)整理，不合并多个独立网页规避。禁止将网页正文转排、复制到Word、打印或转换为PDF、截图封装、改扩展名，即使注明转排来源也不合规。不保存TXT作为输入。网页中真实附件链接下载到发布机构提供的原始文件属于原件下载。

HTML按规范保留完整相关正文、来源和必要图片并检查桌面、窄屏及离线阅读；其他原件无需套用HTML样式。所有检查按实际完成情况记录。

### 不足与下载受限

候选缺少足够有效材料时补找合规来源，仍不足则换方向。下载失败先尝试合理公开入口，不反复无效抓取或用低质量材料凑数：

- 核心内容未核读且影响可解性：换候选，不猜写标答。
- 内容已核读、答案可验证，仅原件本地保存受限：可保留“待补附件”版本，写《需手动下载说明.md》，列准确URL、文件名和用途，题目和题单标明状态及已取得/待补份数。

实际齐备不足6份不能宣称题包完成。`附件/`只放公开输入及必要本地资源；标答、评分、思路、计算底表、来源制作记录和下载说明放在其外。

## 四、完整求解及独立复核

先检查版本、统计范围、原始精度与舍入，再判断材料差异是错误、合理解释还是证据不足。完成参数选择、公式、关键中间值和最终结果。重要结果采用独立推导、汇总核对、守恒、边界或反例检查，不以重复运行同一脚本代替复核。

存在多种有依据解释时给出分支及结果；比较情景时分清固定条件、变动参数、互斥情形及诊断假设。未公开信息只能给出有边界的判断及具体补证要求，缺口使主要任务不可解则换方向。

每题嵌入一个规模有限、与主决定有关的小问题，让被测智能体实际构造求解对象、计算并复核，增加有业务意义的工作。例如从多材料构造带预算容量约束的分配方案或跨期间费用关系，结果须影响方案、金额、排序、可行性或处理意见。不能仅摘录结论或代入单一公式，也不强制编程、工具次数、人为等待或无意义枚举。

题干给足输入、范围、精度和约束，要求说明构造依据、计算结果及复核结论，但不提供完整模型、全部组合或逐步解法。出题者先完整求解并独立复核，将构造、来源、中间值、结果及核验依据写入标答，设置对应考点并纳入100分。《出题记录.md》简记为何需要实际构造、可能耗时步骤和已完成验证，不承诺未经实测的耗时。

复杂计算、多情景或关键证据争议适合委派独立复核：提供原始输入、业务问题和必要约定，要求重新推导，不能仅评价现有答案是否合理。主智能体解决分歧后定稿，记录修正依据。无子智能体时自行用独立路径完成同样的核验。

## 五、统一制作题目、考点与标答

读取[题目模板](../assets/题目模板.md)和[评分细则](项目文档/怎么写考点.md)。主智能体统一编写，子智能体按需检查缺条件、泄题、评分对应或计算遗漏，只提交问题清单和建议。

题干像业务交办，说明对象、时点、范围、用途及交付要求。工作义务明确，但不提前揭示应由模型发现的异常、正确结论和解题步骤。采用原件中确定事实，不让作答者自选简单算例。

任务类型按最终用途选一类：经营与投资决策；数据、财务与业务运营；法务、合规与交易支持；客户与专业项目交付；持续运营与团队协作；工程、产品与专业研究。行业职业按模板固定填写。

作答思路说明合理路径、材料用途、关键判断和易错处。完整标答写入文本字段，交代证据位置、依据、公式参数、中间结果、最终意见及适用条件；开放结论给出具体参考意见和可接受范围，不只写提纲、概数或“见底表”。必要数值可用文字、公式、编号段落或对应年份的数列表达，无需制作参考答案附件。

模板是唯一字段定义；题目只包含一个Markdown表格，单元格用`<br>`换行并处理竖线，不嵌套第二个表格。

## 六、保存、验收、润色与登记

在项目 `题目收集/` 下用实际出题日期及未占用序号建立 `YYYY_MMDD_序号/`，序号至少两位，同时检查题单编号。不得覆盖已有目录或将审查时点当成出题日期。

目录包含 `题目.md`、`附件/`、`出题记录.md`，仅有待补文件时增加 `需手动下载说明.md`。不得只在聊天交题，也不在技能目录保存题包或工作文件。

已落盘保留的题包立即登记题单，草稿或未完成如实简注；纯探索候选不登记。每题一行：`- 编号｜任务名称：一句话概括真实对象和核心工作。` 保留历史，新题追加，同目录修订更新原行，另存版本注明源题。只记必要状态，不扩展为材料或评分日志。

交付前实质验收：

1. 查重范围真实，业务对象准确，题干、证据、完整解答和考点对应，主要任务可解。
2. 按第三节逐份核对实际文件、来源、计数、长材料骨干和跨材料关系，排除网页转换规避；题目清单、路径和取得状态一致，答案及制作记录未混入输入。
3. 按第四节确认小问题条件完整、构造求解及独立复核成立；按评分细则核对100分、逐项全部条件、覆盖范围及承前计算保护，并确认题目考点字段开头实际写有全对满分、否则0分的评分规则。
4. 被测模型交付与模板格式正确；测试及验证状态真实，不用格式、耗时或未实测自评代替难度证据。

将结果和剩余问题简记在《出题记录.md》。实质验收后，主智能体必须读取[最后去AI味](最后去AI味.md)，直接修改本题原文件的题干、考点、思路和标答，随后核对参数、事实、结果、分值、引用与表格。若润色发现实质错误，返回受影响阶段修正并复验，不把改答案当成文字调整。仅需文字修订的旧题直接执行该环节及相关核对。

最终更新题单名称及真实状态，重新读取本轮条目确认与题目一致，无需遍历历史核账。出题记录简记润色、核验状态及有实质影响的复核分歧，不复制全部对话。

回复简要给出任务名称、题目路径、核心难点、有效附件份数和齐备情况、待实测或真实测试状态、题单编号路径及最后润色情况，不重复贴整份答案。合理探索后仍无可行方向时说明候选和具体阻碍，有保留题包则登记真实状态，不硬凑完成。
